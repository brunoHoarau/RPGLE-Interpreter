# Incrément 5a — fichiers écran (cœur, terminal scripté)

Spec : `docs/superpowers/specs/2026-10-10-ecrans-design.md` (sections 1 à 3, 5, 6 ; la section 4 = 5b).
Branche `feat/ecrans`. TDD, `npm run check` vert à chaque tâche, un commit par tâche (message en français).
Tout ce qui n'est pas listé est **refusé explicitement** (`unsupported` / `NotSupportedError`, message en français).

## Contraintes globales

- Aucun fichier de `src/` > 400 lignes. Simulateur et description : `src/screens/` ; côté interpréteur :
  `src/interpreter/screens/`. `declare.ts` / `operations.ts` des fichiers ne reçoivent qu'un aiguillage.
- Le simulateur ne lit jamais l'état de l'interpréteur : il ne connaît que `SpecialCall` (protocole SPECIAL, spec §1).
- Noms de fichiers, formats, zones, touches : majuscules dans `displays.json` ; insensibles à la casse dans le source.
- Tout est synchrone (le terminal panneau de 5b bloquera dans un worker).

## Points d'attention (à tester dans la tâche indiquée)

1. `exfmt fmt01` en minuscules, format déclaré `FMT01` → fonctionne (T5).
2. Zone écran de même nom qu'une zone d'un fichier base de même type → partagée ; type différent → erreur (T4).
3. Constante `if` selon un indicateur que la touche précédente vient de positionner (F5 puis réaffichage) (T5).
4. Saisie numérique vide ou `-` seul → zéro ; `1,5` dans `zoned(5:2)` → 1.50 ; `12345` dans `zoned(5:2)` → message (T3).
5. Valeur négative aller-retour dans AREA (`-12` en zoned(3:0) → `01K` → -12) (T2).

## T1 — `displays.json` : chargement et validation

- `src/screens/definition.ts` : `DisplayFileDefinition { indara: boolean; keys: KeyMap; formats: { [n: string]: DisplayFormat } }`,
  `DisplayFormat { keys: KeyMap; constants: DisplayConstant[]; fields: DisplayField[] }`,
  `DisplayField { name; type: DataTypeNode; usage: 'I'|'O'|'B'|'H'; row?; col?; length: number; condition?: Condition }`,
  `DisplayConstant { row; col; text; condition? }`, `Condition = { indicator: number; negated: boolean }[]`,
  `KeyMap = Map<string, number | null>` (clés normalisées `CA03`, `CF05`, `PAGEUP`, `PAGEDOWN` ;
  `ROLLDOWN`→`PAGEUP`, `ROLLUP`→`PAGEDOWN`). Fonction `normalizeDisplays(raw, path)`.
- Type via `parseFieldType` (`src/files/field-types.ts`) ; seuls char et zoned (NUMERIC SQL) acceptés.
  `length` = char n ; zoned = p.
- Erreurs (avec le chemin) : nom non majuscule, `usage` inconnu, `row/col` absents (sauf H) ou zone hors 24×80,
  touche inconnue, indicateur hors 01–99, même touche au niveau fichier et format, `if` mal formé, zone en double.
- `ExecutionContext.displays` (vide par défaut), lu par `loadContextFromFolder` depuis `displays.json`.
- Tests : `test/context.test.js` (un cas valide complet + chaque erreur).

## T2 — Protocole et image AREA

- `src/screens/protocol.ts` : `SpecialCall`, `SpecialRoutine`, `Terminal`, `Screen`, `ScreenInput` **exactement** comme la spec §1.
- `src/screens/area.ts` : `encodeArea(fields: DisplayField[], values: Map<string, string|number>) : string` et
  `decodeArea(fields, area) : Map<string, string|number>` ; char complété à blanc ; zoned = p chiffres, zéros de tête,
  dernière position négative `}`/`J`…`R` ; longueur = somme des longueurs (H comprises).
  `indicatorsString(get: (n) => boolean)` / lecture inverse (99 caractères `0`/`1`).
- Tests : `test/ecrans.test.js` (aller-retour char, zoned positif / négatif / zéro, décimales, point d'attention 5).

## T3 — Simulateur d'écran et terminal scripté

- `src/screens/simulator.ts` : `class ScreenSimulator implements SpecialRoutine`, construit avec
  `(file: string, definition: DisplayFileDefinition, terminal: Terminal)`.
  `O`/`C` : statut 0. `W` : format inconnu → statut 2 ; construit le `Screen` (spec §3.2, valeurs §3.5),
  le mémorise, `terminal.show`. `R` : spec §3.3 et §3.4 — boucle `terminal.input(screen)` ; en cas de refus,
  `screen.message = 'Touche F5 non autorisée'` (ou message de zone) et `terminal.show` puis nouvelle saisie.
  CA → AREA inchangée. Indicateurs : toutes les touches du format et du fichier à `0`, la touche à `1`.
- `src/screens/input-values.ts` : conversion d'une saisie en valeur de zone (point d'attention 4).
- `src/screens/scripted-terminal.ts` : `class ScriptedTerminal implements Terminal` (spec §1, terminal scripté),
  `shown: Screen[]`.
- Tests : simulateur seul (appels `SpecialCall` à la main) : W puis R ENTER / CF05 / CA03 / PAGEDOWN, touche
  non autorisée, saisies numériques, R sur un autre format → statut 2, scénario épuisé / désordonné.

## T4 — Analyse et déclaration `DCL-F … WORKSTN`

- Parser (`src/parser/files.ts`) : `WORKSTN` → `node.device = 'workstn'` (PRINTER, SPECIAL restent refusés) ;
  `INDDS(nom)` → `node.indds` (refusé sans WORKSTN) ; avec WORKSTN, refuser KEYED, EXTFILE, EXTDESC, RENAME,
  PREFIX, USROPN (« … sur un fichier écran »). USAGE par défaut : input + output. Champs dans `FileDeclarationNode` (`src/types.ts`).
- `InterpreterOptions.screens?: (file: string, definition: DisplayFileDefinition) => SpecialRoutine`
  (fabrique : un simulateur par fichier écran). Sans elle → `NotSupportedError` « fichier écran : exécution interactive requise ».
- `src/interpreter/screens/declare.ts` `declareDisplayFile(s, node, parameters)`, appelée en tête de `declareFile`
  si `node.device === 'workstn'` : fichier absent de `displays.json` → erreur ; INDDS sans `indara` → erreur ;
  INDDS doit être une DS de 99 octets au moins. Zones de tous les formats déclarées via le même contrôle que les
  fichiers base (`s.fileFields`) ; même nom dans deux formats avec types différents → erreur.
  État `s.displays: Map<string, DisplayState>` (clé : fichier **et** formats) ;
  `DisplayState { file; definition; routine: SpecialRoutine; indds?: string }`. Appel `O` à la déclaration ;
  `C` en fin de programme. Nom déjà utilisé (fichier base, autre écran) → erreur, comme `declareFile`.
- `test/helpers.js` : `runScreens(code, displays, inputs, context?)` → `{ output, shown }` (fabrique =
  `ScreenSimulator` + un `ScriptedTerminal` partagé).
- Tests : `test/ecrans.test.js` + refus dans `test/unsupported.test.js`.

## T5 — WRITE, READ, EXFMT

- Lexer : `'exfmt': TokenType.EXFMT` ; ajout à `FILE_OPERATION_TOKENS` ; retrait de `UNSUPPORTED_OPCODES` ;
  `'exfmt'` dans `FileOperationNode['operation']`. Parser : `EXFMT nom;` seulement (clé, DS, extenseur → refus).
- Aiguillage dans `executeFileOperation` (`src/interpreter/files/operations.ts`) : `s.displays.has(node.file)` →
  `executeScreenOperation(s, node)` (`src/interpreter/screens/operations.ts`). EXFMT sur un fichier base → erreur.
  Refus : WRITE/READ sur le nom du fichier, CHAIN/UPDATE/DELETE/SETLL/…, extenseurs, DS résultat, OPEN/CLOSE.
- `W` : AREA = `encodeArea` des variables du format ; indicateurs = `*IN01…99` ou les sous-zones `ind` de INDDS
  par position. `R` : `decodeArea` → affectation de toutes les zones du format ; indicateurs recopiés
  (`*INnn` ou sous-zones INDDS). EXFMT = W puis R. Statut 2 → erreur « fichier écran X : … (erreur nnnnn) ».
- Tests : programme avec EXFMT (ENTER, CF05, CA03 avec variables inchangées), WRITE puis READ, INDDS,
  `if` conditionné, points d'attention 1 et 3.
