# Incrément 5a — fichiers écran (cœur, mode scripté)

Spec : `docs/superpowers/specs/2026-10-10-ecrans-design.md` (sections 1 à 3, 5, 6 ; la section 4 = 5b).
Branche `feat/ecrans`. TDD, `npm run check` vert à chaque tâche, un commit par tâche (message en français).
Tout ce qui n'est pas listé est **refusé explicitement** (`unsupported` / `NotSupportedError`, message en français).

## Contraintes globales

- Aucun fichier de `src/` > 400 lignes ; le code écran vit dans `src/screens/` (description, E/S) et
  `src/interpreter/screens/` (exécution). Ne pas grossir `declare.ts` / `operations.ts` au-delà d'un aiguillage.
- Noms de fichiers, formats, zones, touches : majuscules dans `displays.json` ; insensibles à la casse dans le source.
- Interpréteur synchrone : `ScreenIO.read` est synchrone (le worker de 5b s'y branchera sans changer l'interpréteur).

## Points d'attention (non couverts par les tâches sans test explicite — à tester dans la tâche indiquée)

1. `exfmt fmt01` en minuscules, format déclaré `FMT01` → fonctionne (T4).
2. Zone écran de même nom qu'une zone d'un fichier base de même type → partagée ; type différent → erreur (T3).
3. Zone `if` affichée selon un indicateur que la touche précédente vient de positionner (`*IN03` puis WRITE) (T4).
4. Saisie numérique vide ou `-` seul → zéro ; `1,5` dans `zoned(5:2)` → 1.50 ; `12345` dans `zoned(5:2)` → message (T5).
5. Deux écrans successifs sur des formats différents du même fichier, scénario désordonné → erreur claire (T5).

## T1 — `displays.json` : chargement et validation

- `src/screens/definition.ts` : types `DisplayFileDefinition { indara: boolean; keys: KeyMap; formats: { [n]: DisplayFormat } }`,
  `DisplayFormat { keys: KeyMap; constants: DisplayConstant[]; fields: DisplayField[] }`,
  `DisplayField { name; type: DataTypeNode; usage: 'I'|'O'|'B'|'H'; row?; col?; length: number; condition?: Condition }`,
  `DisplayConstant { row; col; text; condition? }`, `Condition = { indicator: number; negated: boolean }[]`,
  `KeyMap = Map<string, number | null>` (clé normalisée : `CA03`, `CF05`, `PAGEUP`, `PAGEDOWN` ; `ROLLDOWN`→`PAGEUP`,
  `ROLLUP`→`PAGEDOWN`). Fonction `normalizeDisplays(raw, path)`.
- Type de zone via `parseFieldType` (`src/files/field-types.ts`) ; seuls char, zoned, packed acceptés ;
  `length` = longueur affichée (char n ; numérique = chiffres, sans virgule ni signe).
- Erreurs (avec le chemin du fichier) : nom non majuscule, `usage` inconnu, `row/col` absents (sauf H) ou zone hors de 24×80,
  touche inconnue, indicateur hors 01–99, même touche au niveau fichier et format, `if` mal formé, zone en double dans un format.
- `ExecutionContext.displays` (vide par défaut), lu par `loadContextFromFolder` depuis `displays.json`.
- Tests : `test/context.test.js` (un cas valide complet + chaque erreur).

## T2 — `ScreenIO` et fournisseur scripté

- `src/screens/io.ts` : interfaces `ScreenIO`, `Screen`, `ReadRequest`, `ScreenInput` **exactement** comme la spec §1.
- `src/screens/scripted.ts` : `class ScriptedScreenIO implements ScreenIO` construit avec
  `{ format, file?, key?, fields? }[]` ; `shown: Screen[]` (chaque `show`) ; `read` vérifie `format` (et `file` si donné),
  renvoie `key` (défaut `ENTER`) et `fields` convertis en chaînes ; liste épuisée → erreur
  « aucune saisie prévue pour le format FMT01 (lecture n° 4) » ; si `request.screen.message` est présent → erreur
  « saisie refusée par l'écran : <message> » (le scénario ne réessaie pas).
- `InterpreterOptions.screenIO?: ScreenIO`. Exporter `ScriptedScreenIO` depuis `out/screens/scripted`.
- `test/helpers.js` : `runScreens(code, displays, inputs, context?)` → `{ output: lignes DSPLY, shown: Screen[] }`.
- Tests : unitaires de `ScriptedScreenIO` dans `test/ecrans.test.js`.

## T3 — Analyse et déclaration `DCL-F … WORKSTN`

- Parser (`src/parser/files.ts`) : `WORKSTN` → `node.device = 'workstn'` (PRINTER, SPECIAL restent refusés) ;
  `INDDS(nom)` → `node.indds` (refusé sans WORKSTN) ; avec WORKSTN, refuser KEYED, EXTFILE, EXTDESC, RENAME, PREFIX, USROPN
  (« … sur un fichier écran »). USAGE par défaut d'un WORKSTN : input + output. Champs ajoutés à `FileDeclarationNode` (`src/types.ts`).
- Exécution : `src/interpreter/screens/declare.ts` `declareDisplayFile(s, node, parameters)`, appelée en tête de
  `declareFile` si `node.device === 'workstn'`. Sans `s.options.screenIO` → `NotSupportedError`
  « fichier écran : exécution interactive requise ». Fichier absent de `displays.json` → erreur.
  `indara` sans INDDS : accepté ; INDDS sans `indara` → erreur ; INDDS doit être une DS d'au moins 99 octets.
- Zones de tous les formats déclarées comme variables globales via le même contrôle que les fichiers base
  (`s.fileFields` : même type → partagé ; type différent → `incompatibleTypes`) ; même nom de zone dans deux formats
  du même écran avec types différents → erreur.
- État : `s.displays: Map<string, DisplayState>` indexée par nom de fichier **et** nom de format ;
  `DisplayState { file: string; definition; indds?: string; area: boolean[] /* 1..99, mode indara */ }`.
  Nom de format ou de fichier déjà utilisé (fichier base, autre écran) → erreur, comme `declareFile`.
- Tests : `test/ecrans.test.js` + refus dans `test/unsupported.test.js`.

## T4 — WRITE format (affichage)

- `src/interpreter/screens/render.ts` : `buildScreen(s, state, format, message?) : Screen`.
  Indicateurs : `*INnn` si pas `indara` ; sinon `area`, après recopie des sous-zones `ind` de la DS INDDS
  dont la position (1–99) donne le numéro. Zone/constante dont le `if` est faux : absente. H : non transmise.
  Valeurs : char complétée à blanc ; numérique = chiffres avec zéros de tête, sans virgule, `-` à droite si négatif ;
  zone I : blancs / zéros (spec 3.2).
- Aiguillage : dans `executeFileOperation` (`src/interpreter/files/operations.ts`), si `s.displays.has(node.file)` →
  `executeScreenOperation(s, node)` (`src/interpreter/screens/operations.ts`). WRITE sur un format → `show`.
  Refus : WRITE/READ sur le nom du fichier, CHAIN/UPDATE/DELETE/SETLL/…, extenseur (E) ou (N), DS résultat, OPEN/CLOSE.
- Tests : écran affiché (valeurs, constantes conditionnées par `*IN31` et via INDDS, zones I vides, H absente).

## T5 — READ format et EXFMT (saisie)

- Lexer : `'exfmt': TokenType.EXFMT` ; ajouter à `FILE_OPERATION_TOKENS` ; retirer `exfmt` de `UNSUPPORTED_OPCODES` ;
  `'exfmt'` dans l'union `FileOperationNode['operation']`. Parser : `EXFMT nom;` uniquement (clé, DS, extenseur → refus).
  EXFMT sur un fichier base → erreur à l'exécution.
- `src/interpreter/screens/input.ts` : `readScreen(s, state, format)` — boucle :
  `read({ file, format, screen })` ; touche non `ENTER` absente des `keys` (format + fichier) →
  `screen.message = 'Touche F5 non autorisée'` et nouvelle lecture ; zone inconnue, non affichée ou non I/B → erreur ;
  valeur char trop longue ou numérique invalide / trop grande → message et nouvelle lecture
  (saisie numérique : chiffres, `-` en début ou fin, `,` ou `.`, alignée sur les décimales ; vide → 0).
  Puis : ENTER / CF / PAGEUP / PAGEDOWN → zones I et B affichées affectées (non saisie : valeur affichée) ;
  CA → aucune zone affectée ; indicateurs de réponse de toutes les touches du format et du fichier à off,
  celui de la touche à on (`*INnn`, ou `area` puis recopie dans les sous-zones de INDDS).
- EXFMT = WRITE puis `readScreen` sur le même format ; READ format = `readScreen` (l'écran courant doit être ce format,
  sinon erreur « READ FMT02 : le format affiché est FMT01 »).
- Tests : ENTER, CF05, CA03 (variables inchangées), PAGEDOWN, indicateurs via INDDS, touche non autorisée,
  saisies numériques (points d'attention 4), scénario désordonné / épuisé.
