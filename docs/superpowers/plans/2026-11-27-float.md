## Sémantique IBM i retenue (doc IBM 7.4 : outpfloat.htm, bbcharnum.htm, bbeditf.htm, bbfloat.htm)

- `FLOAT(4)` et `FLOAT(8)` ; toute autre longueur, ou `FLOAT` sans longueur : erreur de compilation.
  Valeur initiale 0 ; `INZ(1.5E3)`, `INZ(0.5)`, `INZ(12)` acceptés.
- Un FLOAT(4) stocke `Math.fround(v)` ; un FLOAT(8) un double JS.
- Littéral flottant : `1.5E3`, `4E4`, `1.2e-3`, `5E+2` (mantisse, E/e, signe facultatif, chiffres). Type float(8).
- Expression flottante : si un opérande de + - * / ** est flottant, le résultat est float(8) (doubles JS : rien à changer dans operators.ts).
  Flottante = variable/élément/sous-zone/retour de procédure déclaré FLOAT, littéral flottant, `%FLOAT(...)`,
  `-x`, `%ABS(x)` avec x flottant, opération arithmétique ayant un opérande flottant.
- Format externe (DSPLY, %CHAR, %EDITFLT) : signe toujours écrit (`+` ou `-`), mantisse normalisée, `E`, signe, 3 chiffres d'exposant.
  - 8 octets : 23 caractères, 16 chiffres significatifs : `+1.000000000000000E+000`, `-5.722748027467392E-123`.
  - 4 octets : 14 caractères, 8 chiffres, exposant sur 2 chiffres : `+1.2345678E+03`.
  - Mantisse arrondie au plus proche (`toExponential(15)` / `(6)`) ; zéro : `+0.000000000000000E+000`.
  - %CHAR et DSPLY d'une expression flottante : 23 caractères, sauf variable/élément/sous-zone FLOAT(4) seul : 14.
  - `%EDITFLT(expr numérique)` : 14 si l'argument est une zone FLOAT(4), sinon 23 ; argument décimal/entier converti en float.
    Exemple IBM : f8 = 50000 ; `%EDITFLT(f8 - 4E4)` → `+1.000000000000000E+004`.
- `%FLOAT(numérique ou caractère)` → float(8). Caractère : blancs ignorés, signe, point ou virgule, exposant `E` permis
  (`'-5.2e-1'` → -0.52 ; `' + 5 . 2 '` → 5.2) ; texte invalide → statut 00105 (RNX0105).
  Exemples IBM : p1 packed(15:0)=1, p2 packed(25:13)=3, r packed(15:5) : `r = p1 / p2` → 0.33000 (existant),
  `r = %FLOAT(p1) / p2` → 0.33333.
- Flottant → décimal ou entier (affectation EVAL, paramètre, retour, %INT, %DEC(x:l:d)) : **troncature de la valeur
  binaire exacte** (communauté RPG400-L : utiliser EVAL(H)/%DECH, sinon 0.29 peut donner 0.28).
  Ex. `f = 0.29` (float 8 = 0.28999999999999998) ; `p = f` avec p packed(5:2) → 0.28 ; `%DECH(f:5:2)` → 0.29 ; `%INTH`.
  Mise en œuvre : avant le coerce existant, ramener la valeur à la valeur exacte tronquée au nombre de décimales de la cible
  (développement décimal exact du double via BigInt : mantisse × 2^exposant), puis laisser coerce faire le contrôle de capacité
  (0.28 reste 0.28 après normalize). Ne pas toucher au chemin décimal existant.
- `%DEC(flottant)` sans longueur ni décimales : refusé (`unsupported`, message en français).
- `%SIZE` : 4 ou 8 (ajouter float à SIZED_TYPES, byteLength = longueur).
- Décimal → flottant : conversion du double (rien à faire) ; FLOAT(4) : fround.
- Comparaisons flottant/décimal : numériques (existant).
- Affectation d'un caractère à un flottant, d'un flottant à un caractère : refusées (checkAssignable comme packed).

## Refus explicites (avec test dans `test/unsupported-*.test.js` ou float.test.js)

- `%EDITC`, `%EDITW` d'un flottant (refusés par le compilateur IBM : erreur explicite).
- `%HIVAL`/`%LOVAL` d'un flottant, `%DEC(flottant)` sans précision, FLOAT dans un fichier/SQL (colonne FLOAT/DOUBLE)
  si un chemin l'accepte silencieusement.
- Division flottante par zéro : comportement IBM non vérifié → refuser (NotSupportedError) plutôt qu'Infinity.
- Toute valeur NaN/Infinity produite (débordement 1E308*10) : refuser.
