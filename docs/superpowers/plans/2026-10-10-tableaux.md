# Incrément tableaux + %EDITC + ordre EBCDIC

Objectif : faire tourner `agregation_par_categorie` (DS LIKEREC DIM(*AUTO:10), %LOOKUP sur `films(*).categorie`,
`films(*next) = ds`, SORTA, FOR-EACH, %EDITC 'X'). Branche `feat/tableaux`. TDD, `npm run check` vert à chaque tâche,
un commit par tâche (message en français). Tout ce qui n'est pas listé est **refusé explicitement** (`unsupported`).

## T1 — Ordre de tri EBCDIC (CCSID 297)

- `src/ebcdic.ts` : table CCSID 297 octet → caractère Unicode, générée par le JDK (`Charset IBM297`),
  fichier source : scratchpad `ebcdic297.txt` (256 points de code hexadécimaux, ligne 1). Construire la table inverse.
- `compare()` (`src/interpreter/evaluate/operators.ts`) : deux chaînes se comparent par leurs codes EBCDIC après
  complétion à blanc (inchangée). Ordre attendu : blanc < ponctuation < minuscules < majuscules < chiffres.
- Caractère absent du CCSID 297 (ex. `€`, `œ`) dans une comparaison : `NotSupportedError`.
- Le SQL n'est pas concerné (écart connu, à part).
- Tests : dans le fichier de test des comparaisons existant (`'a' < 'B'`, `'Z' < '0'`, `'é'` placé selon la table).

## T2 — %EDITC(valeur : code)

- 3e argument (*ASTFILL, *CURSYM, monnaie) : refusé. Arité 2 sinon.
- Chiffres et décimales pris du **type déclaré** de l'argument (`declaredType`, comme %CHAR) : packed/zoned(n:d) ;
  int/uns(3|5|10|20) = 3/5/10/20 chiffres, 0 décimale. Pas de type déclaré (littéral, expression) ou float : refusé.
- Table (virgule = séparateur de milliers « , », point décimal « . », DECEDIT par défaut) :

| Code | Milliers | Point | Négatif | Zéro |
|---|---|---|---|---|
| 1 / 2 | oui | oui | aucun | 1 : `.00` ou `0` ; 2 : blancs |
| 3 / 4 | non | oui | aucun | 3 : `.00` ou `0` ; 4 : blancs |
| A / B, C / D | comme 1/2, 3/4 | oui | `CR` en fin | idem |
| J / K, L / M | comme 1/2, 3/4 | oui | `-` en fin | idem |
| N / O, P / Q | comme 1/2, 3/4 | oui | `-` flottant à gauche | idem |
| Z | non | non | aucun | blancs |
| X | aucune mise en forme : chiffres avec zéros de tête, sans point | | négatif refusé | `000…` |
| Y | date : 6 chiffres `nn/nn/nn`, 8 chiffres `nn/nn/nnnn`, zéro de tête suppressé | | refusé | refusé |

- Résultat de longueur fixe : chiffres + séparateurs de milliers + point (si décimales) + place du signe
  (`CR` = 2, `-` = 1, blancs si positif). Suppression des zéros de tête par des blancs jusqu'au point
  (le séparateur de milliers dans la zone supprimée devient blanc). Zéro avec décimales et code « .00 » : `   .00` ;
  sans décimales : `0` en dernière position. Y sur d'autres longueurs : refusé.
- Exemples à tester : zoned(7:2) 12345.67 'J' → `12,345.67 ` ; -12345.67 'J' → `12,345.67-` ; 'A' → `12,345.67CR` ;
  'N' de -5.00 en packed(5:2) → `  -5.00` ; packed(5:2) 0 '1' → `   .00`, '2' → 6 blancs ; zoned(10:0) 94558100 'X'
  → `0094558100` ; 'Z' de 0 → blancs.
- Tests : fichier de test des BIF ; `%EDITC` ajouté à `BUILTINS` et `BUILTIN_ARITY` ; refus dans `test/unsupported.test.js`.

## T3 — Tableaux simples (dcl-s DIM)

- Déclaration : `DIM(n)` (littéral entier 1..16773104 ou constante nommée), `DIM(*AUTO : n)`. INZ s'applique à
  chaque élément. Refusés : `DIM(*VAR…)`, DIM sur sous-zone de DS, paramètre, prototype ; CTDATA, FROMFILE, PERRCD,
  ASCEND, DESCEND, ALT ; LIKE d'un tableau.
- Runtime : valeur = tableau JS d'éléments ; dimension mémorisée dans la portée (`max`, `auto`) ; type de l'élément
  dans `types`. *AUTO commence à 0 élément.
- Parser : noms de tableaux connus (global + procédure, comme les autres noms connus) → `arr(expr)` est un **élément**,
  pas un appel. Nouveau `valueType: 'element'` `{ name, index, field? }` ; `index` = expression | `'*'` | `'*next'`.
  L'affectation reçoit une cible élément (`AssignmentNode.target?`). Retirer le refus « affectation indicée ».
- Index : entier ; fixe : 1..DIM ; *AUTO en lecture 1..%ELEM ; *AUTO en écriture : jusqu'à DIM, au-delà de %ELEM
  le nombre d'éléments passe à l'index (éléments intermédiaires à leur valeur initiale). Hors bornes :
  `RpgError(121)` (`STATUS_ARRAY_INDEX`, RNX0121), interceptable par MONITOR.
- `arr(*next) = x` : *AUTO seulement (sinon erreur de compilation) ; au-delà de DIM → 00121.
- `%ELEM(arr)` : DIM, ou nombre courant pour *AUTO ; argument non tableau → erreur de compilation ;
  `%ELEM(arr) = n` refusé.
- Tableau entier ailleurs (`arr` seul en expression, `arr = x`, `arr(*)` hors %LOOKUP/SORTA, DSPLY, SQL) : refusé
  (« opérations sur un tableau entier »). Élément passé à un paramètre **par référence** : refusé (`NotSupportedError`) ;
  CONST / VALUE acceptés.
- Tests : nouveau `test/tableaux.test.js`.

## T4 — Tableaux de DS

- `dcl-ds d QUALIFIED DIM(n | *AUTO:n) … end-ds`, `LIKEDS(x) DIM(…)`, `LIKEREC(f) DIM(…)`, `EXTNAME(…) QUALIFIED DIM(…)`.
  DS DIM sans QUALIFIED (hors LIKEDS/LIKEREC) : erreur de compilation. LIKEDS d'une DS tableau : refusé.
- `d(i).champ` en lecture/écriture ; `d(i) = autreDs` et `autreDs = d(i)` avec les règles de disposition de
  `assignDataStructure` ; `d(*next) = autreDs` ; `d.champ` sans index ou `d` seul en expression : erreur de compilation.
- Retirer le refus de DIM sur dcl-ds dans `test/unsupported.test.js` (garder les cas encore refusés).

## T5 — %LOOKUP et SORTA

- `%LOOKUP(arg : arr | d(*).champ {: début {: nombre}})` : égalité de `compare()` ; recherche dans les éléments
  courants ; renvoie l'index ou 0 ; début < 1 ou > %ELEM (si %ELEM > 0) → 00121. Types incompatibles → compilation.
  Ne touche pas %FOUND. %LOOKUPLT/LE/GE/GT restent refusés.
- `SORTA[(A|D)] arr | d(*).champ` : ordre de `compare()` (donc EBCDIC), *AUTO sur les éléments courants ;
  pour `d(*).champ` les DS entières sont déplacées. Retirer `sorta` de `UNSUPPORTED_OPCODES`.
  SORTA %SUBARR, SORTA sur tableau à clés multiples : refusés.

## T6 — FOR-EACH

- `FOR-EACH item IN arr | d ; … ENDFOR;` : l'élément est **copié** dans `item` à chaque tour (scalaire : coercition
  vers le type de `item`, catégorie incompatible → compilation ; DS : même disposition, sinon refus comme
  `assignDataStructure`). Nombre d'éléments évalué au départ. LEAVE / ITER comme les autres boucles.
  Après la boucle, `item` garde le dernier élément. Refusés : FOR-EACH(H), `IN %SUBARR/%LIST/%SPLIT/%RANGE`.
